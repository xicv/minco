# Upgrade from Minco 1.0.0 to 1.1.0

Previous published baseline: `1.0.0`

Target version: `1.1.0`

Publication status: `published`

Minco 1.1.0 is published from immutable tag `v1.1.0`. Update the complete
lock-step family together and independently verify registry availability before
changing a production lockfile.

Minco 1.1.0 is an additive release focused on agent-native application
development. It does not change the OpenAPI resource convention, plugin
distribution schema, capability versions, Plan IR, deployment receipts,
read-only MCP catalog, database lifecycle, or application runtime behavior.

## Update the lock-step family

Update every direct Minco dependency together. Most applications only need the
facade and the development control plane:

```bash
cargo update -p minco --precise 1.1.0
cargo install cargo-minco --version 1.1.0 --locked
```

If the application directly depends on smaller Minco crates, update each exact
requirement to `1.1.0` in the same review. Do not mix Minco package lines.
Update locally packaged official plugin descriptors to the `^1.1.0` core
compatibility range at the same time; capability versions do not change.

## Review project-local agent setup

Fresh 1.1 applications generate application-mode `AGENTS.md` instructions.
Existing applications remain unchanged until an operator reviews a plan and
applies its exact digest:

```bash
cargo minco agent plan --target all --json
cargo minco agent sync --target all --expect-plan-digest <sha256> --json
cargo minco agent doctor --target all --json
```

The plan targets `.agents/skills/minco-*`, `.claude/skills/minco-*`, the Minco
ownership receipt, and—only when safe—a minimal Claude `@AGENTS.md` bridge.
Existing user-owned client files are preserved. A conflict requires manual
review; Minco never adopts or overwrites an unknown file.

## Use bounded project context

Agents can request exact project, operation, or task facts without an
arbitrary filesystem or command surface:

```bash
cargo minco agent context --json
cargo minco agent context --operation placeOrder --json
cargo minco agent context --task M0-T01 --json
cargo minco agent eval --target all --json
```

`context` reuses `ProjectView`, caps output at 64 KiB, and performs no command,
network request, write, provider call, or database query. `eval` validates
packaged skill format, installed bytes, client parity, and scenario contracts;
it invokes no model and is not hosted or production evidence.

## Compatibility and rollback

The agent surface is opt-in and project-local. Removing managed projections
from a consumer does not alter application behavior, but deletion is not an
implicit Minco CLI operation: inspect `.minco/agent-manifest.json` and remove
only paths whose bytes still match the receipt.

An application can return its Cargo dependencies and `cargo-minco` tool to
1.0.0 without a data migration. Retain the reviewed 1.0 lockfile and do not
reuse a 1.1 projection receipt with a 1.0 CLI.

Source qualification, hosted CI, registry publication, documentation
deployment, AWS deployment, runtime behavior and production approval remain
independent evidence states throughout the upgrade.
