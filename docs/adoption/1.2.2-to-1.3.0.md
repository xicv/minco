# Upgrade from Minco 1.2.2 to 1.3.0

Published baseline: `1.2.2`

Candidate workspace version: `1.3.0`

Candidate publication status: `unpublished`

Minco 1.3.0 is an additive lock-step minor candidate for the complete
34-package family. It introduces one opt-in, provider-specific Waffo Pancake
integration and a version-matched Waffo Agent Skill. Existing applications do
not change behavior unless they select the new facade feature and compose the
plugin.

## What changes

- `minco-plugin-payments-waffo` adds signed typed actions, hosted guest and
  authenticated checkout, read-only GraphQL, verified standard HTTP webhooks,
  a bounded JSON CLI and deterministic offline fakes.
- The facade adds `plugin-payments-waffo`; it is absent from default features
  and enables the existing idempotency plugin explicitly.
- `cargo minco plugin` catalog and archive metadata include the beta plugin,
  its provider-managed cost classification and its no-hidden-retry policy.
- The packaged Codex and Claude bundle grows from eight to nine skills and
  retains cumulative release-feature and scenario coverage.
- The frozen 1.3.0 candidate manual, generated references and validation
  receipts describe the same exact source boundary.

## Application migration

No migration is required for applications that remain on 1.2.2. After 1.3.0
publication is independently verified, update every selected Minco crate
together. To adopt Waffo explicitly:

```toml
[dependencies]
minco = { version = "1.3.0", features = ["plugin-payments-waffo"] }
minco-plugin-payments-waffo = "1.3.0"
```

Configure only opaque `env:` or application-resolved `ssm:` secret references.
Keep application orders, subscriptions, entitlements and payment projections
outside the plugin. Treat checkout returns as navigation; update authoritative
state only after a verified webhook or an explicitly authorised query.

During candidate review, use the exact repository source. Do not assume 1.3.0
archives exist on crates.io.

## Public API and compatibility

The new crate, facade feature, Waffo service/client/transport types, CLI binary,
descriptor capabilities and Agent Skill are additive public surfaces. No
existing 1.2 Rust API, serialized Plan IR, stable diagnostic, CLI output or
plugin capability is removed or changed.

Official descriptors advance in lock-step to `^1.3.0` so source, compiled
descriptors and generated plans agree. A third-party descriptor on `^1.2.2`
does not admit the new minor line; review it and advance its compatibility range
only when its implementation and tests support 1.3.0. Descriptor and capability
schema versions do not change.

## Security, cost and recovery

Production writes require exact environment agreement and an explicit
persisted guard. Session tokens avoid generic persistence, signed requests do
not redirect, custom API origins are test-only, checkout URLs are validated
before token fragments are attached, and raw webhooks are authenticated before
decoding. Provider hints are untrusted response data.

The plugin adds no polling, schedule, queue, database, fixed compute, AWS
resource or always-on Minco control plane. Waffo pricing and application data
retention remain explicit external/application concerns.

Rollback by removing the facade feature and provider composition, then restore
the complete application dependency family to 1.2.2. Do not rewrite an
immutable release tag or published archive. Preserve application-owned payment
records and reconcile ambiguous provider outcomes using the original Waffo
idempotency key rather than blind retry.

## Evidence boundary

Local source, compiler, test, package, docs and clean-Linux qualification are
separate from merge, tag, registry publication, docs.rs, Pages and live Waffo
proof. This candidate makes no live provider request, payment, deployment or
production-readiness claim.
