# Adopt Minco 1.8.0 from 1.7.0

Published baseline: `1.8.0`
Current workspace version: `1.8.0`
Publication status: `published`

Minco 1.8.0 is an additive lock-step release. It makes direct object
transfers available through explicit plugin composition without changing the
existing buffering store, single-upload, application authorization or
production topology defaults.

## Upgrade the coordinated family

Advance every Minco dependency and the `cargo-minco` control plane together.
The exact tag, all 34 registry records and GitHub release are independently
verified. All packages remain in the existing family, and official descriptors
move `core_compatibility` to `^1.8.0`; do not mix lock-step versions.

## Compose object transfers explicitly

The older `ObjectStore` and managed single-request upload contracts remain
available. To add the lifecycle, compose the additive streaming, private
download and multipart services from one provider configuration, then inject
an application implementation of `ObjectTransferHttpUseCases` with
`ManagedObjectStoragePlugin::with_http_api`.

That application port owns principal authorization, purpose and tenant quotas,
durable upload/session records, stable logical object IDs, conditional pointer
updates, retention and inspection verdicts. Provider keys and signed requests
are not ownership records. S3 is the production-targeted direct byte plane;
other providers need their own bounded stream/sign/multipart implementation or
an application-owned protected byte endpoint.

## Update browser and mobile clients

- Send large bytes directly to the returned private provider request; the HTTP
  API carries no file body.
- Persist non-secret pending state and the latest accepted receipt per part.
  Retry failed parts and abort cancelled sessions.
- Keep completion quarantined until application content policy accepts it.
- Upload replacements to a new immutable revision and publish the logical
  pointer only with the current strong `If-Match`.
- Stop a download by cancelling the client request. Resume with a new range
  grant bound to the same provider validator.
- Cache private bytes by logical object and revision, then revalidate authorized
  metadata with `If-None-Match`; a `304` avoids another grant and transfer.

The completion JSON body is capped at 3 MiB, part receipts at 10,000, and each
provider part `ETag` at 64 bytes. Configure exact provider CORS and lifecycle
cleanup for incomplete multipart state. Do not log URLs, signatures, upload IDs
or temporary credentials.

## Review validation and cost

Checksum, exact size, media type and provider metadata establish integrity, not
safe content. Retain purpose-specific magic-byte, decoding, malware or other
inspection policy where the product needs it. The transfer cost projection is
structural: confirm current regional storage, request, egress, acceleration and
edge rates separately. The default still adds no CDN, acceleration, scanner,
schedule, fixed compute, NAT Gateway or provisioned concurrency.

## Roll back safely

The additive APIs can remain unused while an application returns to its 1.7.0
lockfile. Do not delete newly uploaded or superseded objects as part of a crate
rollback. Reconcile pending multipart sessions, logical pointers, quarantine
records and retention policy explicitly, then abort only exact owned incomplete
sessions that are safe to remove.
