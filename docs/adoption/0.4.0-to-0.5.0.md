# Upgrade from Minco 0.4.0 to 0.5.0

Published baseline: `0.4.0`
Target version: `0.5.0`
Publication status: `published`
MSRV: Rust `1.97.1`

Minco `0.5.0` is a coordinated pre-1.0 minor release. It standardizes an
opt-in resource API surface, adds structured zero-idle cost evidence and
separates the authoritative local quality matrix from bounded hosted
qualification. Upgrade the full selected Minco family together; do not mix
`0.4.0` and `0.5.0` crates.

All 28 exact packages, their docs.rs routes and the external consumer feature
matrix were independently verified after publication. A source version, pull
request, merge, tag, package dry run and registry publication remain separate
states for later releases.

## Resource API convention

The convention is OpenAPI-first and opt-in. A resource family must declare a
single `x-minco-resource` identity and the complete `create`, `list`, `read`,
`update` and `delete` action set before `cargo minco make resource` will select
it.

| Action | Success shape | Concurrency/idempotency |
|---|---|---|
| Create | `201` with `{ "data": ... }` | Required `Idempotency-Key`; immutable replay of the original response |
| List | `200` with `{ "data": [...], "page": { "hasMore": ..., "nextCursor": ... } }` | Bounded opaque cursor; declared stable sort/filter allowlists |
| Read | `200` with `{ "data": ... }` | Strong `ETag` |
| Update | `200` with `{ "data": ... }` | Required `If-Match`; `428` when missing, `412` when stale |
| Delete | `204` with no body | Required `If-Match`; `428` when missing, `412` when stale |

Errors use `application/problem+json` and stable Problem codes. Resource IDs,
examples, security, success responses and Problem responses remain part of the
reviewed OpenAPI contract.

This is a thin wire-contract and scaffolding layer, not a generic CRUD
repository. Authorization, field validation, domain invariants, soft-delete
policy, audit, retention and transaction boundaries remain in application use
cases. Application-owned, use-case-shaped ports keep SQLx, Axum and AWS SDKs
outside domain/application crates. DynamoDB still requires access-pattern-
specific ports rather than relational emulation.

## Migrating an existing resource

1. Capture the current public contract and client fixtures.
2. Add the complete `x-minco-resource` family, success envelopes, Problem
   responses, pagination declarations, ETags and precondition headers to
   OpenAPI.
3. Run:

   ```text
   cargo minco contract check
   cargo minco contract sync
   cargo minco make resource <singular-name> --dry-run --json
   ```

4. Add failing application tests for authorization, validation and
   fail-before-persistence behavior.
5. Implement domain invariants and one use case per action through narrow
   application-owned ports.
6. Add real adapter transaction/concurrency tests and Axum `oneshot` contract
   tests.
7. Update clients to unwrap `data`, follow only returned opaque cursors, retain
   strong ETags and send `If-Match` for update/delete.
8. Run `cargo minco explain <operationId> --json` for every action and review
   the Plan/IAM/cost consequences.

The Orders reference is the executable example for all five actions. Its
idempotent create replay remains the original `201` representation even after
the resource is updated or deleted.

## Plan and zero-idle cost evidence

Plan cost output now distinguishes typed cost classes and pricing confidence.
Request/storage dimensions, retained resources, incomplete allowance data and
eligibility/Region-dependent prices stay visible instead of being collapsed
into a misleading zero-dollar estimate.

The minimal AWS profile still provisions no NAT Gateway, fixed application
compute, provisioned concurrency or scheduled wakeup. This is a claim about
provisioned application compute at idle, not a promise that storage, retained
logs, DNS, secrets, databases, requests or explicitly selected schedules are
free.

One-time schedule cleanup may record completion deletion, residual resources
and a manual fallback. Minco currently fails closed when the checked SAM/
CloudFormation schema cannot represent provider cleanup semantics; research
does not silently become a production adapter.

## Local and hosted verification

`./scripts/quality.sh` remains the authoritative source gate. It includes
static/repository truth, formatting, the complete workspace compiler/test/
Clippy matrix, generated applications, browser tests, documentation,
dependency/security checks and exact source identity.

The manual GitHub workflow has two explicit profiles:

- `essential` is the default clean-Linux merge-safety check;
- `release` independently repeats the complete quality/package matrix and adds
  Plan/SAM, both native ARM64 Lambda artifacts and optional Rustack/E2E.

Neither hosted profile contacts AWS or publishes crates. Live AWS proof,
merge, tag, publication, registry verification, consumer installation and
docs.rs rendering retain independent authorization and evidence.

## Package and compatibility review

The package inventory remains 28 lock-step crates. After changing selected
dependencies, regenerate the lockfile and run:

```text
cargo minco upgrade report --json
cargo minco contract diff --against <reviewed-0.4.0-revision> --json
cargo tree -e normal,build
cargo check -p minco --no-default-features --locked
cargo check -p minco --locked
cargo check -p minco --all-features --locked
```

Resolve every breaking or uncertain contract item against actual request and
response directions. Package qualification does not authorize
`scripts/release/publish.sh --execute`.

## Deferred boundaries

This release does not complete rollback/canary, static-site domains,
review-environment cleanup, the versioned documentation product, plugin
distribution/conformance, multi-application adoption or the 1.0 freeze. It
does not add a hosted Minco control plane.
