# Upgrade from Minco 1.3.0 to 1.4.0

Published baseline: `1.4.0`

Workspace version: `1.4.0`

Publication status: `published`

Minco 1.4.0 is an additive maintenance minor. It releases the reviewed
homepage presentation and reproducible language/package refresh completed after
1.3.0. It does not add a framework capability, public Rust API, serialized Plan
IR field, CLI command, provider topology, package or live-provider claim.

## What changes

- all 34 publishable packages advance together to 1.4.0;
- official `minco-plugin.json` descriptors advance in lock-step to
  `core_compatibility = "^1.4.0"`;
- Minco-owned hashing, HMAC and Base64 implementations use `sha2` 0.11, `hmac`
  0.13 and `base64` 0.23 while preserving existing byte contracts;
- the repository toolchain remains Rust 1.97.1 and adopts the reviewed uv,
  Node LTS, Playwright, VitePress-compatible Vite and immutable action pins;
- the frozen 1.4.0 manual includes the corrected homepage diagram and card
  alignment with desktop/mobile browser regressions; and
- all nine packaged Codex and Claude skills point to the 1.4.0 manual and carry
  cumulative release-maintenance coverage.

Vite 8 remains deferred because the current VitePress 1.6.4 boundary is tested
with Vite 6.4.3. This release does not widen that compatibility surface merely
to adopt an upstream major.

## Application migration

Update every direct Minco dependency in one change:

```toml
[dependencies]
minco = { version = "1.4.0", features = ["sqlx-postgres", "aws-lambda"] }
```

Keep explicitly imported Minco crates on the same exact version. Regenerate the
application lockfile with Cargo, then run its normal contract, compiler, test
and deployment-plan checks. Do not copy Minco's repository lockfile into an
application.

Third-party plugins declaring `^1.3.0` remain SemVer-compatible unless they
deliberately require a 1.4.0-only contract. Official descriptors advance to
`^1.4.0` so their source, compiled crate family and distribution metadata stay
lock-step and reviewable.

## Agent projection migration

Install `cargo-minco` 1.4.0, inspect the plan, and approve the exact digest:

```bash
cargo minco agent plan --target all --json
cargo minco agent sync --target all --expect-plan-digest <sha256> --json
cargo minco agent eval --target all --json
```

The projection updates only Minco-owned skill files. It does not invoke a
model, contact a provider, overwrite user-owned instructions or grant release,
deployment, database or production authority.

## Compatibility review

Public Rust signatures, Cargo feature meaning, diagnostic identities, CLI JSON,
plugin capability IDs, release manifests, Plan IR, deployment topology and
provider selection are unchanged. The official descriptor version advance is
intentional distribution metadata, not runtime discovery or dynamic loading.

The dependency migration is covered by exact digest/signature fixtures, the
full workspace tests, generated application consumers, package archive tests,
Rustack and local E2E qualification. Those checks are source evidence only;
performance stays `NOT RUN` and no current live-provider result is inferred.

## Rollback

An application may revert all Minco dependencies and its lockfile to 1.3.0 if
its own data, configuration and
deployment compatibility review permits it. Never rewrite or delete an
immutable tag or published crate version, and never rebuild an artifact during
promotion or rollback.
