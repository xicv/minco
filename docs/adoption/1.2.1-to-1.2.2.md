# Upgrade from Minco 1.2.1 to 1.2.2

Published baseline: `1.2.1`

Candidate workspace version: `1.2.2`

Candidate publication status: `unpublished`

Minco 1.2.2 is a SemVer-compatible lock-step patch for the complete 33-package
family. It hardens the public Signal documentation presentation and adds
regression coverage for the CSS cascade that controls the homepage operating
model. It does not change application runtime behavior, public Rust APIs,
serialized contracts, plugin capabilities, deployment topology or mutation
authority.

## What changes

- The public contract-to-cloud SVG uses shorter, bounded labels that remain
  inside their intended nodes.
- The homepage operating model explicitly wins over VitePress prose defaults,
  suppressing native ordered-list markers and sibling margins without blocking
  existing tablet or mobile grid overrides.
- Browser coverage checks computed list style and spacing on both projects and
  exact top alignment on desktop, where the cards form one row.
- The cumulative agent bundle teaches release, review and web-application
  workflows to treat versioned documentation presentation as release content.

## Application migration

No application source migration is required. After independent publication is
confirmed, update every Minco crate in the application together:

```bash
cargo update -p minco --precise 1.2.2
cargo minco agent plan --target all --json
```

Review the returned plan and synchronize only with its exact current digest.
The projected skills retain their existing names, trigger semantics, paths and
mutation boundaries.

## Plugin compatibility

Official plugin descriptors advance in lock-step to `^1.2.2` so checked source,
compiled descriptors and the generated plan agree. Descriptor schemas,
capability IDs, defaults and static composition do not change. Third-party
plugins may retain `^1.2.1`, which admits compatible 1.2 patch releases, unless
they intentionally require a later API.

## Evidence and rollback

Source, docs build, browser, local release, clean-Linux, tag, registry, docs.rs,
Pages and provider/runtime evidence remain separate claims. This patch creates
no AWS application resource and establishes no production SLO.

Rollback application dependencies and reinstall the 1.2.1 agent bundle if the
patch must be withdrawn. Do not rewrite the immutable `v1.2.1` tag or any
published crate archive.
