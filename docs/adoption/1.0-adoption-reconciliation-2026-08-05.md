## CGSP slice

the workspace boundary, its platform layer opts into bounded HTTP and plugin
features, the API selects the S3 adapter for Feedback, and the worker selects
the bounded SQS runtime. Neither the domain nor application crate depends on
Minco, Axum, SQLx, Lambda or an AWS SDK.

categories, shopping carts, customer addresses, customer accounts, market
profiles and product drafts. Those slices reuse Minco's wire and concurrency

## Framework conclusions

1. Contract-only adoption is a real first step, not a partial runtime
   migration. Both applications validate this boundary.
2. Minco's resource convention scales across multiple product-owned resources
   without a generic CRUD repository or framework-owned business behavior.
3. Static plugin selection and application-owned ports remain the right seam.
   Neither application justifies dynamic loading or a global service locator.
4. Product deployment controllers, authorization, RLS, schemas and workflows
   stay outside core. A provider adapter may implement a port without taking
   over application policy.
5. Local/hosted evidence never upgrades itself to live/provider proof. A
   product-authored live record is still distinct from a provider check run by
   this task.
6. Compatibility bridges are removable only through their application-owned
   observation, rollback and data-retention gates.

The actionable candidate boundary is summarized in the
[supported matrix](../reference/supported-matrix.md). This reconciliation
supplied the application evidence; M12-T04 subsequently recorded the actual
source-level [1.0 compatibility freeze](../reference/compatibility.md). Neither
record proves merge, publication or product deployment.
