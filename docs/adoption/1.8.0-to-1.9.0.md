# Adopt Minco 1.9.0 from 1.8.0

Published baseline: `1.9.0`
Current workspace version: `1.9.0`
Publication status: `published`

Minco 1.9.0 is an additive lock-step release. It adds an opt-in API Gateway
HTTP traffic policy and a hardened negotiated response-compression boundary
without changing any existing public Rust API, serialized contract, plugin
capability or production topology default.

## Upgrade the coordinated family

Advance every Minco dependency and the `cargo-minco` control plane together.
All packages remain in the existing 34-crate family; do not mix lock-step
versions. The exact `v1.9.0` tag, all 34 registry records and the GitHub release are
independently verified.

## Select an ingress traffic policy

The ordinary SAM renderers are unchanged. When the application wants coarse
request-rate and burst protection at the managed ingress before Lambda
invocation, compose a `HttpTrafficPolicy` with one optional default
`TrafficBudget` plus canonical operation-ID overrides and render with
`render_sam_with_traffic_policy` (or the code-URI variants) so the same
settings land on both the `$default` and candidate stages.

The policy resolves operation IDs against the reviewed deployment plan and
fails closed on unknown operations, plans that repeat an operation ID,
overrides that collapse onto one route key, invalid budgets and ambiguous
rendered stage markers. It adds no AWS resource, Redis, counter, worker,
schedule or provisioned capacity. API Gateway throttling remains best-effort:
it can still incur API Gateway request charges, cannot exceed account-level
limits, and is not an authorization or per-user control.

## Keep the hardened compression boundary

`HttpRuntimeConfig::default()` still enables negotiated compression; the field
shape is unchanged. The implementation now compresses only known-size
responses of at least 1 KiB (`RESPONSE_COMPRESSION_MIN_BYTES`) at the fastest
gzip level, keeps Tower HTTP's gRPC/image/SSE exclusions composed, never
recompresses an already-encoded response, and proves `lambda_http` binary
transport for compressed bodies.

For responses that combine secrets with attacker-controlled reflection, insert
the additive `DisableResponseCompression` response extension on that response
only; global `HttpRuntimeConfig::compression = false` remains the whole-
application opt-out. Do not reflect credentials, CSRF or session secrets into
compressed bodies.

## Review client behavior

- Browsers and native HTTP stacks keep negotiating `Accept-Encoding` and
  decompressing transparently; application JavaScript never implements a gzip
  decoder.
- Treat `429` as authoritative regardless of whether API Gateway or the
  application produced it; provider throttling bodies do not use Minco Problem
  Details.
- Static assets remain CloudFront automatic Brotli/gzip; no dynamic CloudFront
  distribution is introduced.

## Roll back safely

Both additions are opt-in. An application that selects no traffic policy and
keeps default compression configuration observes no behavior change beyond the
documented 1 KiB threshold, and can return to its 1.8.0 lockfile without any
migration.
