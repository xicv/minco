# Adopting the Minco 1.10.0 candidate from 1.9.0

Published baseline: `1.9.0`

Candidate workspace version: `1.10.0`

Candidate publication status: `unpublished`

Minco 1.10.0 is an additive candidate. Continue using exact published 1.9.0
dependencies in applications until the complete candidate family is separately
qualified, tagged, published, and independently verified.

## New package boundary

The candidate adds `minco-interaction` and `minco-plugin-ticketing`, increasing
the lock-step public family from 34 to 36 packages. Both are first-publication
candidates: neither package name, owner set, or trusted publisher is claimed by
the source tree.

`minco-interaction` holds provider-neutral support-entry, attachment,
transcription, transition, and post-commit activity primitives. Feedback keeps
its existing public transcription names and feature flags through re-exports.

## Ticketing remains opt-in

Enable `plugin-ticketing` only when the application owns a project-scoped
support workflow and supplies the required identity, object-storage,
notification, audit, event, health, persistence, and portal boundaries. The
plugin is disabled by default and adds no hosted portal, mailbox poller,
schedule, or fixed compute.

Inspect the archive-visible contract before adoption:

```bash
cargo minco plugin explain ticketing --json
cargo minco plugin validate
```

The browser launcher sends bounded untrusted context to a same-origin BFF. The
BFF derives requester identity, project, permissions, and return policy server
side. One-time handoffs are stored only as digests and are consumed atomically
with the first authoritative ticket/session result.

## Evidence boundary

Local Rust, SQLite, Node, Playwright, documentation, conformance, package, and
quality checks do not prove crates.io ownership, hosted Linux, live providers,
deployment, a branded portal, browser-store publication, or production use.
