# Upgrade from Minco 1.4.0 to 1.5.0

Published baseline: `1.5.0`

Current workspace version: `1.5.0`

Publication status: `published`

Minco 1.5.0 is an additive minor release. It packages the measured local
assurance, golden-topology cost-regression and typed side-effect-fake work
already merged after 1.4.0. It does not add a provider capability, package,
deployment topology, default feature, live-provider claim or production SLO.

## What changes

- all 34 publishable packages advance together to 1.5.0;
- official `minco-plugin.json` descriptors advance in lock-step to
  `core_compatibility = "^1.5.0"`;
- `FakeMessageHandler`, `FakeEventPublisher`, `FakeObjectStore`,
  `FakeFeedbackStore` and `FakeMailTransport` are additive public test helpers
  implementing their existing owning ports;
- the release gate retains pinned selected-crate coverage, bounded mutation,
  nextest/Cargo parity and SemVer comparison against immutable `v1.4.0`;
- the provider-free cost baseline reproduces seven reviewed Orders topologies
  without provider prices or a production budget;
- the frozen 1.5.0 manual documents these test and evidence boundaries; and
- all nine packaged Codex and Claude skills carry cumulative 1.5 release
  coverage.

## Application migration

No production code change is required. Update every direct
Minco dependency together:

```toml
[dependencies]
minco = { version = "1.5.0", features = ["sqlx-postgres", "aws-lambda"] }
```

Keep explicitly imported Minco crates on the same exact version and regenerate
the application lockfile with Cargo. Existing tests may adopt a fake directly
from the package that owns the corresponding port; do not add a generic mock
facade or select the fake in a production composition root.

Use only synthetic values in attempt snapshots. Fake `Debug` output is
redacted, but the typed attempts intentionally retain the values a test needs
to assert. Adapter, hosted and live-provider checks remain separate.

## Agent projection migration

When updating Minco workflow projections, inspect and approve the
version-matched projection:

```bash
cargo minco agent plan --target all --json
cargo minco agent sync --target all --expect-plan-digest <sha256> --json
cargo minco agent eval --target all --json
```

The deterministic evaluation proves skill format, projection bytes and
scenario contracts only. Application-specific Codex/Claude outcome evaluation
and measured human-review effort remain `NOT RUN`; the release does not infer
them from a passing script.

## Compatibility review

The five fake types are additive public Rust interfaces. Existing public
signatures, serialized Plan IR, receipt schemas, CLI paths and JSON, diagnostic
identities, Cargo feature meaning, default selection, production adapter
selection and provider topology remain unchanged. Official descriptors advance
to `^1.5.0` for source/distribution coherence; third-party `^1.4.0`
descriptors remain SemVer-compatible unless they deliberately require a
1.5-only fake.

The measured assurance and cost baselines are repository qualification
evidence, not runtime dependencies. They add no application process, network
call, schedule, poller, fixed compute or control plane.

## Verification

Run the consuming application's ordinary contract, compiler, test and Plan
checks. When adopting a fake, add one regression through its real public port
covering success and the intended one-shot failure or retry behavior. Keep real
engine/provider conformance in its independent lane.

The release source passed the complete local quality and release matrix.
Clean-Linux, registry, docs.rs, Pages, live-provider, deployment and production
evidence are obtained independently and are not implied by source preparation.

## Rollback

An application may revert the complete lock-step family to 1.4.0 only when its
own source, data, configuration and deployment compatibility review permits
it. Never rewrite a tag, published crate or exact release artifact.
