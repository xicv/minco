# Adopt Minco 1.7.0 from 1.6.0

Published baseline: `1.6.0`
Candidate workspace version: `1.7.0`
Candidate publication status: `unpublished`

Minco 1.7.0 is an additive lock-step candidate. It changes only fresh automatic
local-service runtime selection; public application, plugin, Plan IR, database
and deployment contracts remain compatible with 1.6.0.

## Upgrade the coordinated family

Advance every Minco dependency and the `cargo-minco` control plane together once
the exact 1.7.0 family is published. Official plugin descriptors move their
`core_compatibility` requirement to `^1.7.0`; do not mix lock-step versions.

## Review local runtime selection

On a qualified Apple silicon host with Apple Container 1.2.x ready, a fresh
`MINCO_CONTAINER_RUNTIME=auto` start now chooses Apple Container before Docker.
Docker remains the fallback when Apple Container is unavailable or unsupported.

The preference applies only when no lifecycle receipt or exact owned resource
exists. Existing receipts and resources still select their recorded runtime,
and resources present in both runtimes remain a fail-closed ambiguity. Explicit
`MINCO_CONTAINER_RUNTIME=docker` and `MINCO_CONTAINER_RUNTIME=apple` selections
remain authoritative.

## Migrate data explicitly

The upgrade does not copy, compare or delete persistent volumes. If an
application deliberately moves PostgreSQL from Docker to Apple Container:

1. stop writers and identify the exact owned source and destination;
2. create a recoverable logical backup;
3. restore into the intended Apple volume;
4. compare schema/catalog and application row fingerprints;
5. exercise start, query and stop through the source-built 1.7 control plane;
6. remove only the exact inactive Docker resources after separate authorization.

Keep Docker and the project-owned Compose boundary for non-Apple hosts and
Compose-only custom services. No production runtime, AWS resource, Plan IR or
cloud-cost behavior changes in 1.7.0.
