# M14-T55 - Adopt the contract-derived request boundary for ticketing mutations

Closes the final open Phase-2 finding: ticketing handlers hand-rolled
JSON extraction instead of the ADR-0047 generated boundary.

## Goal

- The plugin contract declares `x-minco-request-validation: generated`;
  a deterministic `src/generated.rs` is committed for the plugin contract
  (regenerated by a guarded test, freshness-asserted by the same test on
  every run — the app-level `minco contract sync` path is app-manifest
  scoped, so the plugin owns its deterministic sync).
- Request-body handlers extract through `ValidatedJson<generated::…>` so
  schema-derived bounds are enforced by the generated `ContractValidate`
  implementations before any handler logic; each handler then maps the
  DTO into the existing application inputs (handlers still contain no
  business rules).
- Manual query parsing for list endpoints stays bounded and strict as it
  is today; adopting `ValidatedQuery` for cursor filters is follow-up
  once the generator covers query schemas.

## Non-goals

- Coarse per-operation authorization claims (`authorize_operation`):
  ticketing's permission model is finer-grained than operation scope and
  stays in the service layer.
- Query-parameter generation (not covered by the generator today).

## Evidence

Run 2026-08-24 in the `minco-task-m14-t55` workspace:

- Contract now satisfies every generated-validation rule the checker
  enforces: all request bodies reference named `components.schemas`
  objects (ten new named schemas: `TicketReply`, `TicketAssignment`,
  `TicketQueueTransfer`, `TicketPriorityChange`, `TicketStatusChange`,
  `SessionExchange`, `AgentManagement`, plus inline bodies replaced),
  unsupported request-reachable `pattern` assertions replaced by length
  bounds (the exact-hex digest check stays in the application use case).
- `src/generated.rs` (1.7k lines) committed deterministically; the
  guarded test regenerates under `UPDATE_MINCO_GENERATED=1` and asserts
  byte equality on every run. Generator improvements shipped in
  `minco-contract` so generated output is lint-clean (`#![allow]`s) and
  formatting-stable (`#![cfg_attr(rustfmt, rustfmt_skip)]` — discovered
  when formatting a parent module staled the child through rustfmt's
  module following); the orders app's `generated.rs` was re-synced with
  the standard `minco contract sync` and its consumers re-tested.
- All eleven request-body handlers extract through
  `ValidatedJson<generated::…>`; the hand-rolled `ApiJson` extractor and
  its rejection mapper are deleted; wire-to-application mappings live in
  a dedicated `wire` module; one test expectation updated truthfully
  (malformed JSON now answers with the standard `invalid_json` problem
  code).
