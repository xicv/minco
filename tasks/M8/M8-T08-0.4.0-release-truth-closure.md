## Goal

Replace the pre-release `0.4.0` repository narrative with independently
verifiable published truth, retain the historical candidate evidence without
presenting it as current, and activate one exact next task.

## Acceptance

- README, status, handoff, publishing guidance and repository truth identify
  `0.4.0` as the published 28-package baseline;
- a post-release registry mode requires every exact workspace version and
  treats absent, yanked or unavailable registry evidence as failure;
- repository truth rejects a current published baseline with a partial package
  count or retained first-publication candidates;
- release, local/hosted qualification, bounded AWS proof, promotion, cleanup
  and publication remain separate evidence categories;
- M8 closes and exactly one next implementation task becomes ready.

## Non-goals

- changing Rust APIs or runtime behavior;
- publishing another crate, tag or GitHub release;
- creating or mutating AWS resources;
- replacing historical pre-release evidence with unsupported claims.

## Completion evidence

- publish-validator registry fixtures pass for exact presence, missing-version,
  yanked-version and unavailable-registry behavior;
- repository-truth fixtures pass all 19 cases, including live-guide drift,
  partial published-family and retained-candidate rejection;
- the live post-release registry verifier completed 28 successful lookups with
  zero errors and zero warnings;
- static validation completed with zero errors and zero warnings;
- the full local `./scripts/quality.sh` gate passed, including both fresh
  database scaffolds, all 40 Chromium/Firefox browser cases, Rust tests and
  documentation, dependency policy, vulnerability audits and secret scanning;
- release-source, hosted, AWS/promotion/cleanup and registry evidence remain
  separately described;
- M8 is complete and M10-T07 is the only ready task.
